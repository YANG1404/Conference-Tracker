# Conference Tracker 요구사항 정의서

> 문서 버전: 1.0  
> 기준일: 2026-09-10  
> 대상 서비스: Conference Tracker  
> 관련 문서: `docs/SERVICE_PLAN.md`, `api/openapi.yml`, `docs/DATABASE_MODEL.md`, `docs/conference-tracker.dbml`

## 1. 문서 목적

본 문서는 Conference Tracker의 기능, 데이터, 운영 및 품질 요구사항을 정의한다. 서비스 기획, 화면 구현, API 개발, 데이터 모델링, 테스트 및 운영 검수의 공통 기준으로 사용한다.

요구사항의 범위는 컴퓨터과학 분야의 주요 국제학회 탐색, 공식 일정 확인, Google 로그인 기반 개인화, 기준 카탈로그 및 일정 자동 수집, 관리자 사후 보정 기능이다.

## 2. 서비스 목표

Conference Tracker는 사용자가 여러 사이트를 방문하지 않고도 주요 CS 국제학회의 공식 일정을 월간 캘린더와 시간순 목록에서 확인하도록 지원한다.

서비스는 다음 목표를 가진다.

1. 주요 CS 국제학회의 범위를 일관된 기준 카탈로그로 관리한다.
2. 학회가 발표한 공식 일정명과 원본 시간대를 보존한다.
3. 여러 학회의 일정을 월별로 비교할 수 있게 한다.
4. 비회원에게 탐색 기능을 공개하고 개인화 기능에만 로그인을 요구한다.
5. 자동 수집 결과를 검증 후 우선 공개하고, 관리자는 잘못된 정보만 사후 보정한다.
6. 각 정보의 공식 출처와 마지막 확인 시각을 추적한다.

## 3. 범위

### 3.1 포함 범위

- 컴퓨터과학 분야 주요 국제학회
- 학회명 및 약어 검색
- ACM CCS 기반 분야 필터
- 개최 방식 필터
- 월간 캘린더와 월별 시간순 목록
- 학회 상세정보와 전체 공식 일정
- Google 로그인
- 관심 학회 및 관심 분야 관리
- 기준 CSV 학회 카탈로그 동기화
- CCF-Deadlines 기본 일정 수집
- 공식 홈페이지와 Gemini 기반 상세 일정 추출
- 관리자 학회·일정·링크·분야·출처 관리
- OpenAPI 및 Swagger UI

### 3.2 제외 범위

- 국내·해외 구분 및 필터
- Conference Tracker 내부 논문 제출
- 학회 참가비 결제
- 외부 제출·등록 상태 확인
- 논문 심사 및 채택 결정
- 자체 학회 등급 산정
- 이메일 및 모바일 푸시 알림
- 외부 캘린더 연동
- 사용자 신규 학회 제보와 승인·반려 워크플로
- 개인별 논문 작성 및 제출 진행 상태 관리
- 접근 정책을 우회하는 크롤링

### 3.3 향후 확장 범위

- 국가 및 도시 직접 필터
- ACM CCS 세부 계층 탐색
- 일정 종류 및 마감 임박 필터
- 일정 변경 이력과 자동 변경 감지
- Google·Apple·Outlook Calendar 연동
- 관심 분야 기반 추천
- 연구실 단위 일정 공유
- 사용자 오류 신고
- 이메일 및 모바일 알림

## 4. 사용자 및 권한

| 액터 | 설명 | 주요 권한 |
| --- | --- | --- |
| 비회원 | 로그인하지 않은 공개 사용자 | 검색, 필터, 캘린더·목록·상세 조회, 공식 링크 이동 |
| 로그인 사용자 | Google로 인증한 사용자 | 비회원 기능, 관심 학회, 관심 분야, 내 정보 관리 |
| 관리자 | 관리자 역할이 등록된 Google 사용자 | 공개 데이터 편집, 수집 설정 및 실행 상태 관리 |
| 기준 카탈로그 | 주요 CS 학회 범위를 제공하는 외부 데이터 | CSV 원본 행과 평가 정보 제공 |
| 일정 집계 소스 | 기본 일정을 제공하는 외부 시스템 | 제출 마감, 개최 기간과 장소 제공 |
| 학회 공식 사이트 | 상세 일정의 공식 원본 | 공식 일정명, 날짜, 시간대, 링크 및 장소 제공 |

### 4.1 권한 원칙

- 공개 정보 조회에는 로그인을 요구하지 않는다.
- 개인화 데이터의 조회 및 변경에는 로그인을 요구한다.
- 관리자 API와 관리자 화면은 관리자 역할을 가진 사용자만 이용할 수 있다.
- 비관리자에게 관리자 메뉴를 표시하지 않는다.
- 서버는 화면 노출 여부와 별개로 모든 관리자 API의 권한을 검증한다.

## 5. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 학회 시리즈 | CHI, ICSE처럼 연도와 무관한 정규화 학회 단위 |
| 학회 회차 | CHI 2027처럼 특정 연도에 개최되는 학회 단위 |
| 공식 일정 | 학회가 발표한 제출, 심사, 등록 또는 개최 일정 |
| 일정 구분명 | Papers, Workshops처럼 학회가 사용한 일정 그룹 이름 |
| 기준 카탈로그 | 서비스에 포함할 주요 CS 학회 범위를 정하는 CSV 데이터 |
| 관심 학회 | 로그인 사용자가 저장한 학회 회차 |
| AoE | Anywhere on Earth, UTC-12 기준 시간대 |
| 선공개 | 수집 결과가 검증 규칙을 통과하면 관리자 승인 전에 공개하는 정책 |
| 사후 보정 | 선공개된 정보의 오류나 누락을 관리자가 수정하거나 숨기는 운영 방식 |

## 6. 요구사항 표기 규칙

| 우선순위 | 의미 |
| --- | --- |
| MUST | 현재 서비스 운영에 반드시 필요한 요구사항 |
| SHOULD | 사용성과 운영 품질을 위해 제공해야 하는 요구사항 |
| COULD | 향후 확장 시 고려할 요구사항 |

요구사항 ID는 영역별 접두사와 일련번호를 사용한다.

- `FR-PUB`: 공개 탐색
- `FR-AUTH`: 인증 및 계정
- `FR-PIN`: 관심 학회
- `FR-COL`: 자동 수집
- `FR-ADM`: 관리자
- `DR`: 데이터
- `BR`: 업무 규칙
- `NFR`: 비기능 요구사항

## 7. 기능 요구사항

### 7.1 공개 학회 탐색

| ID | 우선순위 | 요구사항 | 검수 기준 |
| --- | :---: | --- | --- |
| FR-PUB-001 | MUST | 비회원도 메인 화면과 공개 학회 정보를 조회할 수 있어야 한다. | 로그인하지 않은 상태에서 캘린더, 목록 및 상세 화면이 열린다. |
| FR-PUB-002 | MUST | 사용자는 학회명 또는 약어로 학회를 검색할 수 있어야 한다. | 검색어가 학회명 또는 약어에 포함된 회차만 표시된다. |
| FR-PUB-003 | MUST | 사용자는 ACM CCS 대분류를 체크박스로 복수 선택할 수 있어야 한다. | 두 개 이상의 분야를 동시에 선택할 수 있다. |
| FR-PUB-004 | MUST | 분야 복수 선택은 OR 조건으로 동작해야 한다. | 선택한 분야 중 하나 이상에 속하는 학회가 표시된다. |
| FR-PUB-005 | MUST | 사용자는 온라인, 오프라인, 하이브리드 개최 방식으로 필터링할 수 있어야 한다. | 선택한 개최 방식과 일치하는 학회만 표시된다. |
| FR-PUB-006 | MUST | 국내·해외 분류와 필터를 제공하지 않아야 한다. | 메인 화면과 공개 API에 국내·해외 선택 항목 및 `region` 조건이 없다. |
| FR-PUB-007 | MUST | 사용자는 이전 달, 다음 달, 오늘 및 원하는 연·월로 이동할 수 있어야 한다. | 월 경계와 연도 경계를 넘어 정상 이동한다. |
| FR-PUB-008 | MUST | 선택한 달의 일정을 월간 달력 형식으로 표시해야 한다. | 해당 월과 겹치는 공개 일정이 날짜 셀에 표시된다. |
| FR-PUB-009 | MUST | 선택한 달의 일정을 시간순 목록으로 전환해 볼 수 있어야 한다. | 목록 보기에 일정이 날짜 오름차순으로 표시된다. |
| FR-PUB-010 | MUST | 달력의 학회 표기에는 학회 약어와 개최 연도를 함께 표시해야 한다. | `CHI 2027`과 같이 회차 연도가 식별된다. |
| FR-PUB-011 | MUST | 같은 학회·같은 의미·같은 날짜의 중복 일정은 하나로 표시해야 한다. | 하드코딩 데이터와 수집 데이터 또는 CCF와 공식 일정이 중복 노출되지 않는다. |
| FR-PUB-012 | SHOULD | 한 날짜에 표시 공간을 초과하는 일정이 있으면 추가 일정 수를 안내해야 한다. | `+N개 더 보기` 형태로 숨겨진 일정 수를 확인할 수 있다. |
| FR-PUB-013 | MUST | 검색 및 필터 조건을 초기화할 수 있어야 한다. | 초기화 후 전체 분야와 전체 개최 방식이 적용된다. |

### 7.2 학회 상세정보

| ID | 우선순위 | 요구사항 | 검수 기준 |
| --- | :---: | --- | --- |
| FR-PUB-014 | MUST | 사용자가 달력이나 목록에서 학회를 선택하면 상세 패널을 표시해야 한다. | 선택한 회차의 상세정보가 열린다. |
| FR-PUB-015 | MUST | 상세정보에는 학회명, 약어, 개최 연도, 소개 및 ACM CCS 분야를 표시해야 한다. | 저장된 값이 항목별로 표시된다. |
| FR-PUB-016 | MUST | 실제 개최 국가, 도시, 장소 및 개최 방식을 표시해야 한다. | 국내·해외 분류 없이 실제 장소 정보가 표시된다. |
| FR-PUB-017 | MUST | 학회가 발표한 전체 공식 일정을 시간순으로 표시해야 한다. | 일정이 시작 시각 기준 오름차순으로 표시된다. |
| FR-PUB-018 | MUST | 일정 구분명과 공식 일정명을 원문 의미가 유지되도록 표시해야 한다. | `Papers – Submission Due`와 같은 공식 명칭을 확인할 수 있다. |
| FR-PUB-019 | MUST | 미래 일정은 D-N, 당일은 D-Day, 지난 일정은 D+N으로 표시해야 한다. | 기준일 전후의 표시 방향과 일수가 정확하다. |
| FR-PUB-020 | MUST | 시각이 확인된 일정은 KST 변환 시각과 원본 시간대를 함께 표시해야 한다. | AoE 일정에 KST 변환 결과와 `원본 AoE`가 표시된다. |
| FR-PUB-021 | MUST | 날짜만 확인된 일정에 임의의 시간을 생성하지 않아야 한다. | 날짜 일정은 날짜로만 표시된다. |
| FR-PUB-022 | MUST | 공식 홈페이지, 논문 제출, 등록 및 기타 관련 링크를 목적별로 제공해야 한다. | 유효한 외부 URL을 새 페이지에서 열 수 있다. |
| FR-PUB-023 | MUST | 일정별 원본 출처를 확인할 수 있어야 한다. | 출처 URL이 있는 일정에서 원본 페이지로 이동할 수 있다. |
| FR-PUB-024 | SHOULD | 상세 패널은 주요 화면 폭에서 공식 일정명, 기한 및 D-Day가 잘리지 않도록 표시해야 한다. | 데스크톱과 모바일에서 열 정보가 읽을 수 있는 형태로 배치된다. |

### 7.3 Google 로그인 및 계정

| ID | 우선순위 | 요구사항 | 검수 기준 |
| --- | :---: | --- | --- |
| FR-AUTH-001 | MUST | 인증 수단은 Google 로그인을 사용해야 한다. | 유효한 Google ID 토큰으로 로그인할 수 있다. |
| FR-AUTH-002 | MUST | 로그인하지 않아도 공개 탐색 기능을 이용할 수 있어야 한다. | 인증 세션 없이 공개 API가 정상 응답한다. |
| FR-AUTH-003 | MUST | 로그인 성공 후 원래 보던 화면 또는 선택 학회로 복귀해야 한다. | `return_to`가 허용된 내부 경로일 때 해당 위치로 이동한다. |
| FR-AUTH-004 | MUST | 로그인 세션은 HttpOnly, Secure 및 SameSite 속성을 가진 쿠키로 관리해야 한다. | 브라우저 스크립트에서 세션 토큰을 읽을 수 없다. |
| FR-AUTH-005 | MUST | 사용자는 로그아웃할 수 있어야 한다. | 로그아웃 후 세션이 무효화되고 공개 상태로 전환된다. |
| FR-AUTH-006 | MUST | 로그인 상태의 계정 메뉴에는 내 정보, 관리자 페이지(관리자만), 로그아웃을 표시해야 한다. | 일반 사용자에게 관리자 메뉴가 보이지 않는다. |
| FR-AUTH-007 | MUST | 계정 메뉴에 내 정보와 동일한 화면으로 이동하는 별도의 관심 학회 메뉴를 표시하지 않아야 한다. | 계정 메뉴에 중복된 `관심 학회` 항목이 없다. |
| FR-AUTH-008 | MUST | 내 정보 화면에서 Google 이메일과 프로필 이미지를 읽기 전용으로 표시해야 한다. | 사용자가 이메일과 이미지를 직접 수정할 수 없다. |
| FR-AUTH-009 | MUST | 사용자는 표시 이름을 수정할 수 있어야 한다. | 저장 후 새 표시 이름이 계정 영역에 반영된다. |
| FR-AUTH-010 | MUST | 사용자는 관심 분야를 복수 선택하고 하나를 대표 분야로 지정할 수 있어야 한다. | 관심 분야와 대표 분야가 재접속 후에도 유지된다. |

### 7.4 관심 학회

| ID | 우선순위 | 요구사항 | 검수 기준 |
| --- | :---: | --- | --- |
| FR-PIN-001 | MUST | 로그인 사용자는 학회를 관심 학회로 추가하거나 해제할 수 있어야 한다. | 관심 상태 변경 후 달력과 내 정보 화면에 즉시 반영된다. |
| FR-PIN-002 | MUST | 비회원이 관심 기능을 선택하면 Google 로그인 필요 안내를 표시해야 한다. | 안내창에 Google 로그인과 취소 선택지가 표시된다. |
| FR-PIN-003 | MUST | 관심 학회만 보기 기능은 로그인 사용자에게 제공해야 한다. | 활성화 시 저장한 학회만 표시된다. |
| FR-PIN-004 | MUST | 내 정보 화면에서 저장한 관심 학회 목록을 조회하고 해제할 수 있어야 한다. | 목록에서 관심 학회를 제거할 수 있다. |

| FR-PIN-006 | SHOULD | 관심 학회 목록을 다음 일정순 또는 학회명순으로 정렬할 수 있어야 한다. | 정렬 기준 변경 시 순서가 즉시 바뀐다. |
| FR-PIN-007 | MUST | 동일 사용자가 동일 학회를 중복 저장할 수 없어야 한다. | 중복 요청 후에도 관심 관계가 한 건만 존재한다. |

## 11. 핵심 사용자 흐름


## 12. 오류 및 예외 처리

| 상황 | 처리 요구사항 |
| --- | --- |
| 공개 학회 조회 실패 | 기존 화면을 유지하고 재시도 가능한 오류를 안내한다. |
| 인증되지 않은 개인화 요청 | 401과 로그인 필요 메시지를 반환한다. |
| 비관리자의 관리자 요청 | 403을 반환하고 관리자 데이터를 노출하지 않는다. |
| 존재하지 않는 학회 | 404를 반환한다. |
| 잘못된 날짜·시간대 | 422 또는 검증 오류로 저장을 거부한다. |
| 수집 페이지 접근 금지 | 기존 데이터를 유지하고 접근 정책 사유를 기록한다. |
| LLM 근거 불일치 | 후보를 공개 일정으로 반영하지 않고 실패 근거를 기록한다. |
| 외부 사이트 응답 실패 | 재시도 대상으로 기록하되 기존 공개 정보를 유지한다. |

## 14. 완료 조건

다음 조건을 모두 만족하면 현재 MVP 요구사항을 충족한 것으로 본다.

1. 비회원이 주요 CS 국제학회를 검색하고 달력·목록·상세정보를 조회할 수 있다.
2. 국내·해외 구분이 화면, 공개 API 및 영속 모델에 존재하지 않는다.
3. 일정의 공식 명칭, D-Day, KST 변환 시각과 원본 시간대를 확인할 수 있다.
4. 로그인 사용자가 내 정보 화면에서 관심 분야와 관심 학회를 관리할 수 있다.
5. 관리자만 관리자 화면과 API에 접근할 수 있다.
6. 기준 CSV, CCF 및 공식 페이지 기반 수집 결과가 중복 없이 연결된다.
7. 검증된 자동 수집 결과가 공개되고 관리자 수정값과 숨김 상태가 보호된다.
8. OpenAPI 문서와 DBML이 실제 구현 및 본 요구사항과 일치한다.
9. 일정·시간대 자동 테스트, 정적 검사 및 프로덕션 빌드가 통과한다.
