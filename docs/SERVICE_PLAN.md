# Conference Tracker 서비스 기획서

> 개정 기준일: 2026-09-10  
> 본 문서는 현재 구현된 서비스와 확정된 운영 정책을 기준으로 기존 기획서를 개정한 문서이다.

# 1. 서비스 개요

## 1.1 서비스 이름

**Conference Tracker**

## 1.2 서비스 정의

Conference Tracker는 컴퓨터과학 분야의 주요 국제학술대회와 공식 일정을 자동으로 수집하여 월간 캘린더와 시간순 목록으로 제공하는 공개 웹서비스이다.

비회원도 학회 검색, 일정 조회, 분야·개최 방식 필터, 학회 상세정보 및 공식 링크 이용이 가능하다. Google로 로그인한 사용자는 관심 학회를 저장하고, 관심 학회만 모아보며, 자신의 관심 연구 분야를 계정에 저장할 수 있다.

서비스의 학회 범위는 GitHub Gist의 `CS 분야 우수 학술대회 목록.csv`를 기준 카탈로그로 삼는다. CSV의 원본 행은 보존하고, DBLP Key와 학회 약어를 기준으로 동일 학회를 하나의 학회 시리즈로 정규화한다. 연도별 학회 회차와 일정은 별도로 관리한다.

일정 수집은 다음의 하이브리드 구조로 운영한다.

- CCF-Deadlines에서 논문·초록 제출 마감, 개최 기간과 장소 등 기본 일정을 수집한다.
- 학회 공식 홈페이지의 Important Dates 또는 CFP 페이지에서 Gemini 기반 구조화 추출로 상세 공식 일정을 보강한다.
- 수집 결과는 일정 검증 규칙을 통과하면 먼저 공개한다.
- 관리자는 공개된 결과의 원문 근거를 확인하고 잘못되거나 부족한 내용을 사후 수정하거나 숨길 수 있다.

이 구조는 대량의 학회를 빠르게 제공하면서도, 관심도가 높은 학회에는 제출 시작·리뷰 공개·리버털·채택 발표·최종본·등록 일정 등 더 상세한 전체 생애주기를 제공하기 위한 것이다.

## 1.3 서비스 기획 배경

컴퓨팅 분야의 학회 정보는 학회 공식 홈페이지, CFP 페이지, 학술단체 사이트, 논문 제출 시스템 및 여러 일정 집계 서비스에 분산되어 있다. 연구자는 관심 학회를 찾은 뒤에도 초록 등록, 논문 제출, 결과 발표, 리버털, 최종본 제출, 등록 및 개최 일정을 직접 확인하고 개인 일정에 옮겨야 한다.

기존 서비스는 대체로 학회명과 대표 제출 마감일을 목록으로 제공한다. 이 방식은 특정 학회를 확인하기에는 편리하지만 여러 학회의 일정이 겹치는 시기를 비교하거나, 하나의 학회가 발표한 전체 공식 일정을 추적하기에는 부족하다.

Conference Tracker는 다음 문제를 함께 해결한다.

- 컴퓨팅 분야의 주요 학회 범위를 일관된 기준 카탈로그로 관리한다.
- 여러 출처의 일정을 한 화면의 월간 캘린더에 통합한다.
- 학회가 사용한 공식 일정명과 원본 시간대를 보존한다.
- AoE와 지역 시간대를 KST 기준으로 안전하게 변환한다.
- 자동 수집으로 초기 등록 비용을 낮추고 관리자가 오류만 사후 보정하도록 한다.
- 로그인하지 않은 사용자에게도 학회 탐색 기능을 공개한다.

## 1.4 해결하려는 사용자 문제

### 분산된 학회 정보

학회별 공식 홈페이지와 여러 집계 사이트를 반복해서 방문해야 하며, 필요한 정보의 위치와 표현 방식도 서로 다르다.

### 주요 학회의 범위가 불명확한 문제

서비스마다 포함하는 학회 기준이 달라 사용자가 어떤 학회가 누락되었는지 판단하기 어렵다. Conference Tracker는 승인된 CSV를 기준 카탈로그로 사용하여 제공 범위를 명확히 한다.

### 복수 학회 일정의 비교 어려움

같은 기간에 여러 학회의 논문 제출, 채택 발표, 수정본 제출 및 개최 일정이 겹치면 목록만으로 시간적 관계를 파악하기 어렵다.

### 학회별 전체 절차 확인의 어려움

단일 제출 마감일 외에도 다음과 같은 일정이 존재하지만 집계 서비스에는 일부만 제공되는 경우가 많다.

- Submission Opens
- Abstract Registration
- Paper Submission Due
- Reviews Released
- Rebuttal
- Notification
- Camera-Ready
- Author Registration
- Conference Dates

### 시간대 오해 가능성

AoE와 각 지역 시간대를 단순 날짜로 표시하면 한국에서는 날짜가 하루 달라질 수 있다. 원본 시간대와 KST 변환 결과를 함께 제공해야 한다.

### 관심 학회 관리의 어려움

사용자는 많은 학회 중 자신에게 필요한 학회를 저장하고, 해당 학회만 필터링하거나 다음 일정을 가까운 순서로 확인할 필요가 있다.

- 여러 학회의 제출 일정을 관리하는 연구자 및 교수

### 주요 사용 목적

- 학회별 전체 공식 일정 확인

- 공식 홈페이지와 논문 제출 페이지 접근

## 1.6 학회 및 연구 분야 범위

### 기준 학회 카탈로그

1차 서비스의 학회 범위는 GitHub Gist의 `CS 분야 우수 학술대회 목록.csv`에 포함된 모든 원본 행을 기준으로 한다.

- CSV 원본 행과 평가 정보는 보존한다.
- DBLP Key를 우선 식별자로 사용하고 약어를 보조 식별자로 사용한다.
- oral, poster, spotlight처럼 발표 형식만 다른 행은 하나의 학회 시리즈로 병합한다.
- Findings처럼 별도 트랙의 성격이 있는 항목은 학회 내부 트랙 또는 공식 일정 구분명으로 관리할 수 있다.
- CSV에서 사라진 학회는 즉시 삭제하지 않고 비활성화할 수 있다.
- 연도별 회차는 `CHI 2027`처럼 학회 시리즈와 개최 연도를 결합하여 표시한다.

### ACM CCS 연구 분야

학회 분류와 사용자 관심 분야는 동일한 ACM Computing Classification System 기반 대분류를 사용한다.

- 일반 및 참조
- 하드웨어
- 컴퓨터 시스템 구성
- 네트워크
- 소프트웨어 및 소프트웨어 공학
- 계산 이론
- 컴퓨팅 수학
- 정보 시스템
- 보안 및 개인정보 보호
- 인간 중심 컴퓨팅
- 컴퓨팅 방법론
- 응용 컴퓨팅
- 사회 및 전문 주제

하나의 학회에는 여러 분야를 지정할 수 있다. 사용자가 여러 분야를 선택하면 AND가 아니라 OR 조건으로, 선택한 분야 중 하나라도 일치하는 학회를 표시한다.

로그인 사용자는 여러 관심 분야와 하나의 대표 관심 분야를 저장할 수 있다. 이 정보는 향후 추천 기능에 활용하지만, 추천 기능 자체는 현재 MVP 범위에 포함하지 않는다.

## 1.7 학회 제공 범위

서비스는 기준 카탈로그에 포함된 컴퓨터과학 분야의 주요 국제학회를 제공한다.

- ACM·IEEE 등 국제 학술단체 관련 학회
- 국가와 관계없이 국제 연구 커뮤니티가 참여하는 주요 CS 학회
- 온라인·오프라인·하이브리드 방식으로 진행되는 국제학회

국내·해외은 학회의 성격을 나누는 분류로 사용하지 않는다. 대신 실제 개최 국가·도시·장소는 학회 회차의 상세 정보로 유지하고, 메인 화면에서는 ACM CCS 분야와 개최 방식으로 필터링한다.

## 1.8 서비스 목적

Conference Tracker의 목적은 사용자가 여러 사이트를 방문하거나 학회 일정을 직접 옮겨 적지 않고도, 주요 컴퓨팅 학회의 전체 일정을 시간 흐름에 따라 비교하도록 돕는 것이다.

자동 수집 데이터는 검증 규칙을 통과하면 먼저 공개하여 정보의 도달 속도를 높인다. 관리자는 처음부터 모든 학회를 수동 입력하는 대신, 수집 결과의 원문과 근거를 확인하고 잘못된 정보만 수정한다.

## 1.9 핵심 가치

### 명확한 학회 범위

임의로 학회를 추가하는 대신 승인된 CSV를 기준 카탈로그로 사용하고 원본과 정규화 결과를 함께 보존한다.

### 전체 일정 중심의 캘린더

대표 제출 마감일뿐 아니라 학회가 발표한 공식 일정명을 유지하여 월간 캘린더와 시간순 목록으로 제공한다.

### 정확한 날짜와 시간대

시간이 확인된 일정은 UTC로 저장하고 KST로 변환해 표시한다. AoE 등 원본 시간대도 함께 제공한다. 날짜만 확인된 경우 임의의 시간을 만들지 않고 날짜 일정으로 보존한다.

### 공개 탐색과 선택적 로그인

학회 탐색과 일정 조회는 공개하고, 관심 학회와 관심 분야 등 개인화 기능에만 Google 로그인을 요구한다.

### 자동 선공개와 사후 보정

CCF와 공식 페이지 수집 결과를 자동 반영하되, 기존 관리자 보정값과 숨김 상태를 보호한다. 관리자는 원문 근거를 바탕으로 잘못된 내용을 수정할 수 있다.

### 원본 출처 추적

각 일정과 링크에 수집 출처 및 근거를 연결하여 사용자가 공식 페이지에서 최종 정보를 재확인할 수 있도록 한다.

## 2.5 외부 데이터 및 시스템

### 기준 카탈로그

GitHub Gist의 `CS 분야 우수 학술대회 목록.csv`는 학회 포함 범위와 평가 메타데이터를 제공한다. 이 데이터는 일정 출처가 아니라 학회 카탈로그의 기준이다.

### CCF-Deadlines

연도별 학회의 기본 제출 마감, 개최 기간, 장소 및 공식 페이지 링크를 제공한다. 기준 카탈로그와 일치하는 학회만 반영하며, 일치하지 않는 데이터는 임의로 신규 학회로 추가하지 않는다.

### 학회 공식 사이트

Important Dates와 CFP 페이지에서 공식 일정명, 날짜, 시간대, 장소, 설명 및 관련 링크의 근거를 제공한다. 수집기는 robots 정책과 접근 제한을 준수하며, 접근 제한을 우회하지 않는다.

### 외부 제출·등록 시스템

EasyChair, OpenReview, Microsoft CMT 및 학회 자체 시스템 등에서 실제 제출과 등록이 이루어진다. Conference Tracker는 해당 링크만 제공하며 제출·등록 결과를 저장하거나 확인하지 않는다.

## 2.6 자동 수집 및 운영 흐름

```text
기준 CSV 원본 행 동기화
→ DBLP Key·약어 기준 학회 시리즈 정규화
→ CCF 데이터와 연도별 학회 회차 연결
→ 기본 일정·장소·공식 링크 검증
→ 검증된 결과 자동 공개
→ 관심도가 높은 학회부터 공식 페이지 수집
→ Gemini 구조화 추출 및 원문 근거 검증
→ 상세 일정과 누락 메타데이터 자동 보강
→ 관리자 대시보드에서 상태·근거 확인
→ 오류 또는 누락만 편집하거나 숨김 처리
```

### 수집 및 공개 정책

- 기준 카탈로그에 포함된 학회만 CCF 자동 수집 대상으로 사용한다.
- 수집 결과는 임시 저장 후 승인하는 방식이 아니라 검증 후 선공개한다.
- 기존 관리자 수정값은 자동 수집으로 덮어쓰지 않는다.
- 관리자가 숨긴 학회는 재수집 후에도 자동 공개하지 않는다.
- 동일한 회차와 같은 의미의 일정은 출처 우선순위에 따라 중복을 제거한다.
- 공식 또는 수동 보정 일정이 있으면 같은 날짜의 CCF 일반 일정보다 우선한다.
- 원문에서 찾을 수 없는 날짜와 시간은 추정하지 않는다.
- 시간대가 확인된 일정은 UTC로 저장하고 KST로 표시한다.
- 시간대가 확인되지 않은 일정은 날짜 전용 또는 시간 미확인 상태로 저장한다.
- 모든 수집 결과에는 출처 URL, 원문 근거와 마지막 확인 시각을 연결한다.
- 원문이 변경되지 않았다면 Gemini 재호출을 생략한다.
- 수집 실패는 기존 공개 데이터를 삭제하지 않고 운영 화면에 기록한다.

## 2.8 현재 구현에서 제외하거나 변경한 기존 요구사항

기존 기획과 현재 서비스의 차이를 명확히 하기 위해 다음 항목을 변경한다.

- 일반 회원가입과 비밀번호 로그인 대신 Google 로그인만 사용한다.
- 사이트 자체는 비회원에게 공개한다.
- 검색 대상은 현재 학회명과 약어이며, 주최 기관 검색은 향후 범위로 이동한다.
- 현재 보기 방식은 월간 캘린더와 월별 목록이며 주간 보기는 제외한다.
- 국가·도시·일정 상태·논문 제출 가능 여부·마감 임박 직접 필터는 향후 범위로 이동한다.
- 관심 학회의 상단 고정 대신 관심 학회만 보기, 날짜 표시 및 내 정보 목록 관리를 제공한다.
- 알림 기능은 MVP에서 제외한다.
- 외부 사용자의 신규 학회 요청과 검수 대기·승인·반려 흐름은 제거한다.
- 자동 수집 결과는 관리자 승인 후 공개하지 않고 검증 후 먼저 공개한다.
- 관리자의 역할은 전체 데이터의 사전 입력과 승인보다 자동 수집 결과의 사후 확인·보정에 둔다.
- 현재 자동 수집의 핵심 소스는 기준 CSV, CCF-Deadlines 및 공식 학회 페이지이며 KCI·JAMS·RSS 등은 향후 확장 대상으로 둔다.
